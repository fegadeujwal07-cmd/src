Drop planning fix: per-AMR corridors, Excel highways, safety release

Changes made on 23 Nov 2026 so that every loaded AMR can plan its drop leg on its own corridor, highway lanes stay shared by all AMRs, and no AMR is left stuck waiting for a drop plan. 215 changed lines across 7 files in two packages (execution and rmf_traffic). Line numbers are from the files as they are now.

The problem

After pickup, AMRs stood still and never got a drop plan. RMF's task log showed, retrying forever:

Failed to find a plan to move from [Z1] to [P7]. Will retry soon. (same for z12 → Inbound and z17 → Outbound)

  • One AMR's blocked lanes leaked into the others' planning. Each loaded AMR gets its own private closure set (its drop corridor). The cuOpt router caches one route graph per closure set, keyed only by LaneClosure::hash(). That hash OR-ed the 64-bit buckets together, so every large closure set hashed to 0xffffffffffffffff. The first AMR's corridor (amr2, O1 → y6) was cached, and amr3, amr10 and amr1 were then planned on amr2's corridor, where their own pick and drop were not connected.
  • A stuck corridor was never freed. The only release triggers were "planned + moving", "reached drop" and "drop/task ended". With no plan, the closures stayed active (266–374 s at the time of checking) and the AMR was also kept out of task bidding.
  • The Z highways did not match the layout sheet. The code guessed spines from the graph shape and picked x = 14.50 and 52.20 (X11, X37). The orange Z highways in A1462 RFID_Location_Sheet ("1500 loc G0") are X11, X24, X46 and X55.

What changed

  1. Each AMR plans on its own lane set (rmf_traffic). A cached cuOpt graph is reused only when its closure set is identical to the requesting AMR's, and the hash now mixes every bucket so different sets rarely share a key. One AMR's corridor can no longer block another AMR's path.
  2. Highways come from the Excel layout and are shared (execution). X highways Z7 (y 28.35) and Z14 (y 21.00); Z highways X11, X24, X46, X55 (x = (X−1) × 1.45), free only between the X highways as in the sheet. These lanes are open for every loaded AMR, so they are shared; if two AMRs need the same lane at the same time, ECBS / traffic_manager makes one wait. The AMR's own pick and drop columns are free over their full length.
  3. Safety release (execution). If no drop plan on the corridor arrives within drop_corridor_plan_timeout_s (30 s), the corridor is freed and RMF replans the drop on the full graph. Log: no drop plan on the corridor within 30s (falling back to the full graph).
